A perception–action loop, on a phone.

Three stages run in tight loop until your goal is reached. No cloud round-trips.

01

Capture

MediaProjection grabs the current screen. Orion checks for FLAG_SECURE and skips sensitive surfaces automatically.

02

Reason

Gemma runs on the Qualcomm GPU via LiteRT-LM. It reads the accessibility tree and decides the next tap or text input.

03

Act

The Accessibility Service taps the right node or types the right text — and the loop runs again until the goal is done.

Per-frame latency: ~500–2500ms depending on device and backend.

Under the hood.

Hardware-accelerated on-device AI, paired with the Android primitives you already trust.

Model
Gemma 4
E2B and E4B variants, 4-bit quantized. Specialized build for Qualcomm sm8750.
Silicon
Qualcomm GPU
Snapdragon-class GPU runs Gemma directly on-device — no NPU required.
Runtime
LiteRT-LM
Google AI Edge runtime. topK=40, topP=0.95, temperature=0.2 for stable JSON output.
Perception
MediaProjection
Foreground service captures the screen each time the UI settles, then prunes old frames.
Action
Accessibility API
ACTION_CLICK on accessibility nodes, with gesture-based coordinate fallback when needed.
App
Kotlin · Material 3
Min SDK 24, target 36. arm64-v8a. View Binding. No Compose — fast cold start.
